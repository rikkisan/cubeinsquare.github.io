Which Minecraft enchantments can't go together

Seven groups of enchantments exclude each other in Java Edition. An item keeps only one enchantment from each group: one protection type on a piece of armor, one damage enchantment on a weapon, Fortune or Silk Touch, Infinity or Mending. The lists below are read from the game's own data files in 26.3, where each group is an enchantment tag.

By Rikki

All seven groups

Each group is a tag in the game data (exclusive_set/…). An item can carry only one enchantment from a group.

Everything outside these groups combines freely: Unbreaking, Efficiency, Looting, Fire Aspect, Feather Falling, Thorns, Wind Burst, Lunge and both curses have no conflicts at all. Mending is the one that catches people out: it goes on anything except a bow that already has Infinity.

How the game enforces it

Two enchantments conflict when either one lists the other in its group, so the check runs both ways. Mending has no group of its own, yet it still conflicts with Infinity because Infinity's group names it. The game checks in three places:

  • Enchanting table: it never offers a second enchantment from a group the item already uses.
  • Anvil: an enchantment on the book or second item that conflicts with one already on the target is not carried over.
  • /enchant: the command refuses an enchantment that conflicts with one the item already has.

Item data has no such rule. /give, a loot table's set_enchantments function and /item modify write whatever you list:

/give @p minecraft:diamond_sword[minecraft:enchantments={"minecraft:sharpness":5,"minecraft:smite":5}] 1

That is the 1.21.5 – 26.x form; on 1.20.5 – 1.21.4 the pairs go inside {levels:{…}}. Both enchantments stay on the sword and show in its tooltip. No survival player can make such an item, which makes it a clear mark of an admin-made relic, and a giveaway when an item is meant to look player-made. Levels work the same way: the item component accepts any level from 1 to 255, while the table and the anvil stop at the vanilla maximum, such as Sharpness V.

Changing the rules with a data pack

From 1.21 enchantments are data, and each group is a tag file in data/minecraft/tags/enchantment/exclusive_set/: armor, boots, bow, crossbow, damage, mining and riptide. A data pack that replaces one of them changes the rule for the whole world. To let Infinity and Mending share a bow, empty the bow group by saving this as data/minecraft/tags/enchantment/exclusive_set/bow.json:

{
  "replace": true,
  "values": []
}

No restart is needed: /reload picks the file up (we checked on a 26.3 server). After that the table, the anvil and /enchant all accept the pair. The data pack generator builds the folder and pack.mcmeta for your version; the tag file goes inside it.

Enchantments the table never offers

Treasure enchantments never come from an enchanting table: Mending, Frost Walker, Soul Speed, Swift Sneak, Wind Burst, Curse of Binding and Curse of Vanishing (the treasure tag in 26.3). They come from loot chests, fishing and trading, and no librarian sells Soul Speed, Swift Sneak or Wind Burst. Channeling is not a treasure enchantment: a trident can get it from the table. Being treasure and being in a group are separate rules, so Frost Walker still excludes Depth Strider.

In the randomizer

The enchantment & attribute randomizer rolls inside these groups by default, so it never puts Infinity and Mending, or Sharpness and Smite, on one item unless you switch the check off.

FAQ

What two enchantments can't be on a bow?

Infinity and Mending. Power, Punch, Flame and Unbreaking combine with either of them.

Which trident enchantments are incompatible?

Riptide with Loyalty, and Riptide with Channeling. Loyalty and Channeling work together, and Impaling goes with all three.

Which sword enchantments can't go together?

Sharpness, Smite and Bane of Arthropods: a sword takes one of them. Fire Aspect, Knockback, Looting, Sweeping Edge, Unbreaking and Mending fit alongside.

Why can't a pickaxe have Fortune and Silk Touch?

They are one group. Silk Touch drops the block itself and Fortune multiplies the normal drop, so the game lets a tool have only one.

Does Bedrock Edition use the same groups?

Mostly the same pairs, but this page is checked against Java Edition data only. Test on Bedrock before relying on a combination there.
