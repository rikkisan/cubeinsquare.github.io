How to use the Bossbar Builder: what each /bossbar command does

The Bossbar Builder turns a few fields into seven commands: one creates the bar, six configure it. This guide explains every line, where to run it, and the small rules that make a bar fail or linger: duplicate IDs, players who log in later, and bars that survive a restart.

Open the Bossbar BuilderEvent UI and countdowns

Checked for versions: Java Edition 1.13–26.3. /bossbar does not exist in Bedrock Edition.

What the builder generates

With the Ritual charge preset the output is:

/bossbar add cube:ritual_charge {"text":"Ritual charge","color":"white"}
/bossbar set cube:ritual_charge color purple
/bossbar set cube:ritual_charge style notched_10
/bossbar set cube:ritual_charge max 100
/bossbar set cube:ritual_charge value 65
/bossbar set cube:ritual_charge players @a
/bossbar set cube:ritual_charge visible true
LineWhat it doesWatch out for
add <id> <name>Creates the bar and saves it in the world.Fails if a bar with that ID already exists. IDs are lowercase: letters, digits, _ - . / and an optional namespace such as cube:.
colorblue, green, pink, purple, red, white or yellow.It also tints the title, but only when the name has no color of its own. The builder writes "color":"white" into the name, so the title stays white.
styleprogress (one smooth bar) or notched_6, notched_10, notched_12, notched_20.Notches are only drawn on top; the fill is still value ÷ max.
maxThe value of a full bar, from 1 to 2147483647.Use the same unit as value: seconds, ticks, phases or hit points.
valueThe current fill, from 0 up.The builder keeps it at or below max; a larger value just shows a full bar.
playersSets who sees the bar.The selector is resolved once, when the command runs. Someone who logs in later sees nothing until the line runs again.
visibletrue or false.Hides the bar for everyone without forgetting its players or values.

Choosing max, value and style

A bossbar only shows a ratio, so decide first what one unit means. For a timer, max is the length of the event in whatever your update loop counts: seconds if it runs once per second, ticks if it runs every tick. For a ritual that fills as players bring offerings, max is the number of offerings. For a raid in stages, it is the number of stages.

Notched styles help when players should be able to count. Pick a style whose segment count divides evenly by your max: with four phases, notched_12 gives each phase three segments, while notched_6 puts phase boundaries between notches. For countdowns and anything continuous, progress reads best.

The four presets are starting points: Ritual charge (65 of 100), Raid phase II (phase 2 of 4), Evacuation: 3 minutes (180 of 300 seconds left) and Phase break incoming (8 of 12). Change the ID before using one, so that two events never share a bar.

Chat, command blocks or a function file

  • Chat. Paste the lines one at a time; chat takes one command per message. Good for testing a look before an event.
  • Command blocks. One line per block. Run the setup once: impulse blocks behind a button, or a chain started by a single impulse block. Do not put add in a repeating block. From the second run on it fails because the bar exists, and every set that repeats an unchanged value also reports a failure, which breaks conditional chains.
  • Function files. In a .mcfunction file every command goes on its own line without the leading slash. Delete the / from each line the builder gives you, or the function fails to load.

Changing the bar during the event

Once the bar exists, run only the line that changes:

/bossbar set cube:ritual_charge value 80
/bossbar set cube:ritual_charge name {"text":"The circle is complete","color":"gold"}
/bossbar set cube:ritual_charge color yellow

To make the bar follow a real number, copy it from a scoreboard every tick or every second:

execute store result bossbar cube:ritual_charge value run scoreboard players get #offerings ritual

A complete countdown built on this pattern is in the event UI article. For players who arrive in the middle of a scene, run /bossbar set cube:ritual_charge players @a again, for example from the same loop. When nobody new is online the command reports a failure, which is harmless.

Removing the bar

Custom bossbars are stored in the world (in level.dat), so a bar you forget about is still there after a server restart. When the scene ends:

/bossbar remove cube:ritual_charge
/bossbar list

list shows every custom bar that still exists; run it after an event to catch leftovers. If you need the same bar again tomorrow, visible false hides it and keeps its settings.

The title text across versions

The builder writes the name as {"text":"…","color":"white"}. Up to 1.21.4 the game reads it as JSON. From 1.21.5 text components in commands are written in SNBT, and this form is still valid there because SNBT accepts quoted keys, so the same line works on both sides of the change. The shorter {text:"…"} without quotes only works from 1.21.5. A plain quoted string such as "Ritual charge" works everywhere if you do not need formatting.

FAQ

Does a bossbar count down by itself?

No. It shows the last value it was given. A repeating command block or a scheduled function has to update it; see the countdown recipe.

Can different players see different bars?

Yes. Create one bar per group and give each its own selector, for example @a[team=red] and @a[team=blue].

Why is my bar not showing?

Usually the players line never ran, ran before those players were online, or visible is false. /bossbar get cube:ritual_charge players tells you how many players currently see it.

Does this work on Bedrock?

No. /bossbar is a Java Edition command.
