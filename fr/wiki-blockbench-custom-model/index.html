D’un modèle Blockbench à un objet en jeu : export, chemins du pack et branchement

Blockbench crée le modèle ; le resource pack décide quel objet l’affiche. Le fichier du modèle est le même dans toutes les versions depuis la 1.13, mais la façon d’indiquer à un objet quel modèle utiliser a changé en 1.21.4 : la dernière étape dépend donc de votre version.

Constructeur item_modelStructure du resource pack

Vérifié pour les versions : Java Edition 1.20 à 26.3. Les formats Bedrock de Blockbench ne fonctionnent pas en Java Edition.

Dans Blockbench

  • Utilisez le format « Java Block/Item ». Il applique les règles du jeu : chaque cube reste entre −16 et 32 sur chaque axe (trois blocs), et un cube ne tourne qu’autour d’un seul axe, par pas de 22,5° jusqu’à 45°, que toutes les versions acceptent.
  • Réglez l’affichage. L’onglet Display décide de la position du modèle en main, sur la tête, dans un cadre et dans l’inventaire. Sans lui, un grand modèle remplit la case de la barre ou flotte à côté de la main.
  • Nommez les textures selon leur chemin dans le pack. Une texture enregistrée sous assets/cube/textures/item/guild_hammer.png se référence cube:item/guild_hammer. Blockbench écrit cette référence dans le modèle : le chemin doit être juste dès l’export.
  • Exportez par File → Export → Export Block/Item Model, dans assets/cube/models/item/.

Où vont les fichiers

my_pack/
  pack.mcmeta
  assets/cube/
    items/guild_hammer.json          (1.21.4+ only)
    models/item/guild_hammer.json    (exported from Blockbench)
    textures/item/guild_hammer.png

Utilisez votre propre espace de noms (ici cube) plutôt que minecraft pour les nouveaux fichiers, afin d’éviter toute collision avec les ressources vanilla ou un autre pack.

Brancher l’objet en 1.21.4 et au-delà

Une item definition dans items/ indique quel modèle dessiner :

{
  "model": {
    "type": "minecraft:model",
    "model": "cube:item/guild_hammer"
  }
}

L’objet pointe vers ce fichier avec le composant item_model, écrit de la même façon en 1.21.4 et en 1.21.5 – 26.x :

/give @p minecraft:stick[minecraft:item_model="cube:guild_hammer"] 1

Un modèle peut servir plusieurs états d’un objet (chargé, cassé, couleurs de faction) via select, range_dispatch ou condition dans la définition ; le constructeur item_model écrit ces fichiers.

Brancher l’objet en 1.21.3 et avant

Les versions plus anciennes n’ont pas de dossier items/. Le modèle de l’objet vanilla reçoit à la place un override qui bascule selon CustomModelData, dans assets/minecraft/models/item/stick.json :

{
  "parent": "minecraft:item/handheld",
  "textures": { "layer0": "minecraft:item/stick" },
  "overrides": [
    { "predicate": { "custom_model_data": 1 }, "model": "cube:item/guild_hammer" }
  ]
}

La commande fixe ensuite le nombre, en composants en 1.20.5 – 1.21.3 ou en NBT avant :

/give @p minecraft:stick[minecraft:custom_model_data=1] 1
/give @p minecraft:stick{CustomModelData:1} 1

Depuis la 1.21.4, les overrides sont ignorés : c’est la raison la plus fréquente pour laquelle un pack qui « marchait l’an dernier » n’affiche plus que des objets vanilla.

Quand rien n’apparaît

  • Damier violet et noir sur le modèle : le modèle est chargé, pas la texture. Comparez la référence de texture dans le JSON du modèle avec le vrai chemin du PNG.
  • Cube violet et noir à la place du modèle : le fichier du modèle est introuvable ou n’a pas chargé. Vérifiez le chemin dans l’item definition ou l’override, et cherchez le nom du fichier dans le journal du jeu.
  • Énorme ou mal placé en main : les réglages Display sont restés par défaut.
  • Rien ne change après une modification : appuyez sur F3+T en jeu pour recharger les resource packs ; pas besoin de redémarrer.
  • Pack marqué incompatible : pack.mcmeta déclare le format d’une autre version. La page « Pack format » du Minecraft Wiki donne le numéro de chaque version.

Questions fréquentes

Un modèle peut-il servir à plusieurs objets ?

Oui. Plusieurs item definitions, ou plusieurs overrides, peuvent pointer vers le même fichier de modèle.

La texture peut-elle être animée ?

Oui, avec une bande verticale d’images dans le PNG et un fichier .png.mcmeta à côté qui fixe la durée de chaque image.

Quel objet de base doit porter le modèle ?

Celui dont le comportement convient : un bâton ou une carotte sur un bâton pour les accessoires, une épée ou une hache pour les armes, du papier pour les documents. Le modèle ne change que l’apparence.
