Générateur de bossbar : ce que fait chaque commande /bossbar

Le générateur transforme quelques champs en sept commandes : une crée la barre, six la configurent. Ce guide explique chaque ligne, où l’exécuter et les petites règles qui font échouer ou traîner une barre : identifiant déjà pris, joueurs connectés plus tard, barres qui survivent à un redémarrage.

Ouvrir le générateurBossbars d’événement et comptes à rebours

Vérifié pour les versions : Java Edition 1.13–26.3. La commande /bossbar n’existe pas dans Bedrock Edition.

Ce que produit le générateur

Avec le préréglage Ritual charge, on obtient :

/bossbar add cube:ritual_charge {"text":"Ritual charge","color":"white"}
/bossbar set cube:ritual_charge color purple
/bossbar set cube:ritual_charge style notched_10
/bossbar set cube:ritual_charge max 100
/bossbar set cube:ritual_charge value 65
/bossbar set cube:ritual_charge players @a
/bossbar set cube:ritual_charge visible true
LigneRôlePoint d’attention
add <id> <name>Crée la barre et l’enregistre dans le monde.Échoue si une barre porte déjà cet identifiant. L’identifiant s’écrit en minuscules : lettres, chiffres, _ - . / et un espace de noms facultatif comme cube:.
colorblue, green, pink, purple, red, white ou yellow.La couleur teinte aussi le titre, mais seulement si le nom n’a pas sa propre couleur. Le générateur écrit "color":"white" dans le nom : le titre reste donc blanc.
styleprogress (barre continue) ou notched_6, notched_10, notched_12, notched_20.Les crans sont seulement dessinés par-dessus ; le remplissage reste value ÷ max.
maxLa valeur d’une barre pleine, de 1 à 2147483647.Même unité que value : secondes, ticks, phases ou points de vie.
valueLe remplissage actuel, à partir de 0.Le générateur le garde sous max ; une valeur plus grande affiche simplement une barre pleine.
playersDéfinit qui voit la barre.Le sélecteur est évalué une seule fois, au moment de la commande. Un joueur connecté plus tard ne voit rien tant que la ligne n’est pas relancée.

Choisir max, value et le style

Une bossbar n’affiche qu’un rapport : décidez d’abord ce que vaut une unité. Pour un minuteur, max est la durée de l’événement dans l’unité que compte votre boucle de mise à jour : des secondes si elle tourne une fois par seconde, des ticks si elle tourne à chaque tick. Pour un rituel qui se remplit au fil des offrandes, max est le nombre d’offrandes. Pour un raid par étapes, le nombre d’étapes.

Les styles à crans servent quand les joueurs doivent pouvoir compter. Choisissez un nombre de segments divisible par votre max : avec quatre phases, notched_12 donne trois segments par phase, alors qu’avec notched_6 les limites de phase tombent entre deux crans. Pour un compte à rebours ou toute valeur continue, progress se lit le mieux.

Les quatre préréglages sont des points de départ : Ritual charge (65 sur 100), Raid phase II (phase 2 sur 4), Evacuation: 3 minutes (180 secondes restantes sur 300) et Phase break incoming (8 sur 12). Changez l’identifiant avant de vous en servir, pour que deux événements ne partagent jamais la même barre.

Chat, blocs de commande ou fichier de fonction

  • Chat. Collez les lignes une par une : le chat n’accepte qu’une commande par message. Pratique pour essayer un rendu avant l’événement.
  • Blocs de commande. Une ligne par bloc. Lancez la configuration une seule fois : des blocs « impulsion » derrière un bouton, ou une chaîne démarrée par un seul bloc impulsion. Ne mettez pas add dans un bloc « répétition » : dès la deuxième exécution la commande échoue puisque la barre existe, et chaque set qui répète une valeur inchangée échoue aussi, ce qui casse les chaînes conditionnelles.
  • Fichiers de fonction. Dans un fichier .mcfunction, chaque commande tient sur sa propre ligne, sans la barre oblique initiale. Retirez le / de chaque ligne fournie par le générateur, sinon la fonction ne se charge pas.

Modifier la barre pendant l’événement

Une fois la barre créée, relancez seulement la ligne qui change :

/bossbar set cube:ritual_charge value 80
/bossbar set cube:ritual_charge name {"text":"The circle is complete","color":"gold"}
/bossbar set cube:ritual_charge color yellow

Pour que la barre suive un vrai nombre, copiez-le depuis un scoreboard à chaque tick ou chaque seconde :

execute store result bossbar cube:ritual_charge value run scoreboard players get #offerings ritual

Un compte à rebours complet bâti sur ce principe se trouve dans l’article sur les bossbars d’événement. Pour les joueurs qui arrivent en pleine scène, relancez /bossbar set cube:ritual_charge players @a, par exemple dans la même boucle. Si personne de nouveau n’est connecté, la commande signale un échec sans conséquence.

Supprimer la barre

Les bossbars personnalisées sont stockées dans le monde (dans level.dat) : une barre oubliée est toujours là après un redémarrage du serveur. À la fin de la scène :

/bossbar remove cube:ritual_charge
/bossbar list

list affiche toutes les barres encore présentes ; lancez-la après chaque événement pour repérer les oubliées. Si la même barre resservira demain, visible false la cache en gardant ses réglages.

Le texte du titre selon la version

Le générateur écrit le nom sous la forme {"text":"…","color":"white"}. Jusqu’en 1.21.4, le jeu le lit comme du JSON. Depuis la 1.21.5, les composants de texte des commandes s’écrivent en SNBT, et cette forme reste valide puisque le SNBT accepte les clés entre guillemets : la même ligne fonctionne avant et après le changement. La forme courte {text:"…"} sans guillemets ne marche qu’à partir de la 1.21.5. Sans mise en forme, une simple chaîne entre guillemets comme "Ritual charge" fonctionne partout.

Questions fréquentes

Une bossbar décompte-t-elle toute seule ?

Non. Elle affiche la dernière valeur reçue. Un bloc répétition ou une fonction planifiée doit la mettre à jour ; voir la recette du compte à rebours.

Peut-on montrer des barres différentes à des joueurs différents ?

Oui. Créez une barre par groupe, chacune avec son sélecteur, par exemple @a[team=red] et @a[team=blue].

Pourquoi ma barre ne s’affiche-t-elle pas ?

Le plus souvent, la ligne players n’a jamais été exécutée, l’a été avant l’arrivée des joueurs, ou visible vaut false. /bossbar get cube:ritual_charge players indique combien de joueurs la voient en ce moment.

Est-ce que ça marche sur Bedrock ?

Non. /bossbar est une commande de Java Edition.
