Minecraft Item Model Builder

Assemblez les nouveaux fichiers item definition dans assets//items/. Choisissez le type de branche, fixez le fallback, ajoutez les cas et copiez le JSON sans reconstruire la structure fragile à la main.

Lire le guide Ouvrir le générateur

Démarrages rapides

Chargez un modèle de départ puis remplacez les chemins et valeurs par ceux de votre pack.

Configuration de la definition

Ceci est le chemin exact du JSON à créer dans le pack.

Branches

Item definition générée

Pourquoi l’utiliser

  • Ne réécrivez plus la structure model/select/range_dispatch à chaque fois.
  • Gardez le dossier items lisible pour toute l’équipe.
  • Testez une definition avant de lancer une migration plus large du pack.

Avant l’export

  • Vérifiez que les chemins de modèles existent déjà dans le resource pack.
  • Gardez un fallback sûr pour éviter les erreurs visuelles si une branche manque.
  • Si la logique dépend de custom_model_data, vérifiez l’index et la stratégie de slot côté commande.

Utiliser le constructeur

Choisissez comment l’objet sélectionne son modèle, remplissez chemins et branches, et copiez un seul fichier d’item definition.

Bases rapides

Single display model donne un aspect fixe. Selected state bascule avec une condition sur selected. Charge stages suit le temps de recharge avec range_dispatch. Main-hand context utilise select sur la main.

Chemin de la définition

Espace de noms et chemin donnent assets/<namespace>/items/<path>.json. Un objet l’utilise via son composant item_model ; un fichier portant le nom d’un objet vanilla dans l’espace minecraft remplace l’apparence de cet objet.

Modèle de repli

Le modèle affiché quand aucune branche ne correspond. Visez un modèle qui existe, par exemple le vanilla, pour qu’un cas manquant ne s’affiche jamais en texture d’erreur violette et noire.

Propriété et index

Pour custom_model_data, l’index choisit la case : la n-ième chaîne pour select, le n-ième flottant pour range_dispatch.

Branches

Pour select, une branche est une valeur et un modèle. Pour range_dispatch, un seuil et un modèle : le seuil le plus haut sans dépasser la valeur l’emporte. Pour condition, la première branche sert si vrai, la seconde si faux.

Vérifications avant de publier le pack

Les modèles doivent exister

Chaque chemin du fichier mène à assets/<namespace>/models/<path>.json. Une faute de frappe donne la texture d’erreur, pas un message.

Des chaînes contre des chaînes

Un select sur custom_model_data compare du texte : donnez à l’objet custom_model_data={strings:["novice"]} et écrivez novice dans la branche.

L’usure va de 0 à 1

minecraft:damage est normalisé par défaut : 0.25 veut dire qu’un quart de la durabilité est usé, pas 25 points.

Versions

Les item definitions existent depuis la 1.21.4 et restent actuelles jusqu’en 26.3. Avant la 1.21.4, les modèles choisissaient leurs variantes via des overrides dans les fichiers models/item : ce fichier n’y fait rien. Commande associée : /give @p minecraft:book[item_model="cubeinsquare:book/formulary",custom_model_data={strings:["novice"]}].
