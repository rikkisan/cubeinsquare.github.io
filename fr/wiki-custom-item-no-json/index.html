Utiliser le constructeur d’objets custom : des objets sans écrire la commande à la main

Un objet custom dans Minecraft est un objet vanilla avec quelques composants en plus : un nom et un lore pour les joueurs, un ID caché pour votre logique et un hook de modèle pour le resource pack. Le constructeur écrit cette commande /give à partir d’un formulaire, dans la syntaxe de la version choisie : guillemets et crochets ne sont plus votre problème.

Par Rikki

Vérifié pour les versions : Java Edition 1.20 à 26.3.

De quoi est fait un objet custom

CoucheOù elle vitQui la lit
Objet de baseL’identifiant, comme minecraft:paperLe jeu : taille de pile, animation, durabilité
Nom et lorecustom_name, loreLes joueurs
ID cachécustom_data={item_id:"…"}Vos commandes, quêtes, boutiques et villageois
Hook de modèleitem_model, custom_model_dataLe resource pack

Séparer les couches rend l’objet facile à maintenir : on peut le renommer pour une nouvelle saison sans casser la quête qui vérifie son ID caché, et changer son apparence sans toucher ni l’un ni l’autre.

Pas à pas

  1. Version de la commande. Choisissez 1.21.5 – 26.x, 1.21.4, 1.20.5 – 1.21.3 ou avant 1.20.5. Le formulaire n’affiche que les champs que cette version comprend.
  2. Objet de base et quantité. Choisissez la base pour son comportement, pas seulement son aspect : le papier s’empile par 64, un livre ne s’ouvre pas comme un livre écrit, une carotte sur un bâton s’utilise.
  3. ID caché. Un identifiant stable et sobre comme rp.guild.pass. Depuis la 1.20.5, il va dans custom_data ; avant, le constructeur l’écrit comme tag NBT personnel.
  4. Nom et lore. Une ligne de lore par ligne du champ. Le constructeur ajoute italic:false pour que le nom ne ressemble pas à un renommage à l’enclume.
  5. Modèle. Avant la 1.21.4, c’est un seul nombre CustomModelData auquel réagissent les overrides du pack. Depuis la 1.21.4, item_model nomme une item definition : cubeinsquare:item/paper/guild_pass lit assets/cubeinsquare/items/item/paper/guild_pass.json, et les cases float, string, flag et color sont des valeurs sur lesquelles ce fichier peut basculer.
  6. Copier et tester. Le résumé affiche la longueur : au-delà de 256 caractères, la commande demande un bloc de commande plutôt que le chat.

L’exemple, expliqué

« Charger un exemple » remplit le formulaire avec un laissez-passer de guilde. Dans la branche 1.21.5 – 26.x, on obtient :

/give @p minecraft:paper[minecraft:custom_name={text:"Guild archive pass",italic:false},minecraft:lore=[{text:"Stamped for the old city archive.",italic:false}],minecraft:item_model="cubeinsquare:item/paper/guild_pass",minecraft:custom_data={item_id:"rp.guild.pass"},minecraft:custom_model_data={floats:[2047.0f],strings:["guild_pass"],flags:[true],colors:[6138367]}] 1
  • custom_name et lore sont des composants de texte en SNBT, la forme arrivée avec la 1.21.5.
  • item_model pointe vers l’item definition du pack.
  • custom_data porte l’ID caché auquel le serveur peut se fier.
  • custom_model_data porte des valeurs que l’item definition peut tester : un flottant pour range_dispatch, une chaîne pour select, un drapeau pour condition, une couleur pour les teintes.

Le même laissez-passer avant la 1.20.5 tient dans un seul bloc NBT :

/give @p minecraft:paper{CustomModelData:2047,display:{Name:'{"text":"Guild archive pass","italic":false}',Lore:['{"text":"Stamped for the old city archive.","italic":false}']},cube_item_id:"rp.guild.pass"} 1

Vérifier l’ID caché en jeu

Depuis la 1.20.5, les prédicats d’objet testent custom_data directement. La première ligne réagit à chaque joueur qui tient le laissez-passer en main principale ; la seconde en retire un au joueur, ce qui permet à une porte ou une boutique de le « dépenser » :

execute as @a if items entity @s weapon.mainhand *[custom_data~{item_id:"rp.guild.pass"}] run say I carry the guild pass
clear @s *[custom_data~{item_id:"rp.guild.pass"}] 1

Un papier vanilla renommé échoue aux deux tests : le nom n’est pas ce qui est vérifié.

Erreurs fréquentes

  • Changer l’ID caché après coup. Chaque quête, boutique et échange qui le vérifie cesse de reconnaître les anciens objets. Changez plutôt le nom visible.
  • item_model qui pointe vers un modèle. Depuis la 1.21.4, il nomme un fichier dans items/, qui nomme ensuite des modèles dans models/. Viser directement un modèle affiche la texture de modèle manquant.
  • Une commande pour toutes les versions. Les quatre branches existent parce que la syntaxe diffère vraiment : une commande 1.21.4 nomme l’objet {"text":…} en 1.21.5.

Questions fréquentes

Faut-il un resource pack ?

Seulement pour une apparence propre. Nom, lore et ID caché marchent en vanilla sans pack.

À quoi sert la case couleur ?

Une item definition peut teinter une couche de modèle avec les couleurs de custom_model_data : un seul modèle sert plusieurs couleurs de faction.

Un villageois peut-il n’accepter que le vrai objet ?

Oui : mettez le même custom_data dans le prix de l’échange. Le constructeur d’échanges et l’article sur l’économie montrent comment.
