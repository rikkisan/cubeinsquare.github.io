Minecraft Custom Item Catalog

C’est la couche de planification entre "on a quelques objets sympas" et "on a maintenant trente identifiants et plus personne ne sait quel papier correspond à quoi". Gardez un registre local, recherchez-le, exportez-le et arrêtez de deviner.

Entrée du catalogue

Stocké dans ce navigateur

Utilisez-le comme registre local pendant que vous posez IDs, hooks visuels et notes. Exportez en JSON ou CSV quand il faut partager le plan avec l’équipe.

Pourquoi garder un catalogue ?

  • Les IDs cachés en double se repèrent avant de devenir des bugs de quête.
  • Objet de base, nom affiché et hook visuel restent lisibles au même endroit.
  • L’export donne au reste de l’équipe quelque chose de plus utile que des captures.

Les premiers champs utiles

  • Commencez par un ID interne, un ID caché et l’objet de base.
  • Ajoutez ensuite item_model ou CustomModelData selon la version visée.
  • Gardez les notes pour les règles de quête, la propriété d’un PNJ ou les rappels côté pack.

Utiliser le catalogue

Une entrée par objet custom. Le catalogue les garde consultables, signale les collisions et exporte la liste pour le reste de l’équipe.

ID interne et nom visible

L’ID interne est le nom que l’équipe donne à l’objet, comme rp.guild.pass ; le nom visible est ce que lisent les joueurs. Garder les deux évite que le nom visible devienne la seule référence.

Objet de base et version

L’objet vanilla sous-jacent et la version visée décident du hook visuel : CustomModelData numérique avant la 1.21.4, item_model et les nouvelles listes custom_model_data depuis la 1.21.4.

ID caché, hook, tags, notes

L’ID caché est ce que vérifient les commandes et les villageois dans custom_data. Les tags regroupent par faction, quête ou saison ; les notes gardent les règles faciles à oublier.

Signalement des doublons

Le résumé compte les ID cachés et les hooks visuels en double, et chaque entrée en conflit est marquée : deux objets ne répondent jamais au même ID ni ne partagent un modèle par accident.

Ne pas perdre la liste

Elle vit dans ce navigateur

Les entrées sont stockées localement dans votre navigateur. Un autre navigateur ou appareil démarre vide, et effacer les données du site supprime la liste : exportez de temps en temps.

Formats d’export

Le JSON se réimporte plus tard ; le CSV s’ouvre dans n’importe quel tableur ; le Markdown se colle proprement dans un wiki ou un chat d’équipe.

Importer avant de modifier

Si un coéquipier envoie un export JSON, importez-le d’abord puis ajoutez vos entrées, plutôt que de tenir deux listes séparées.

Du catalogue à l’objet

Le catalogue planifie les objets, il n’écrit pas de commandes. Construisez la commande /give dans le constructeur d’objets custom, et donnez un modèle à l’objet avec le constructeur item_model depuis la 1.21.4 ou le générateur de resource packs avant.
