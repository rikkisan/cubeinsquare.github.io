Minecraft Custom Item Catalog

This is the planning layer between "we have a few cool items" and "we now have thirty identifiers and nobody remembers which paper is which". Keep a local registry, search it, export it, and stop guessing.

Read guide Open builder Naming guide

Catalog entry

Stored in this browser

Use this as a local working registry while you sketch IDs, hooks, and notes. Export JSON or CSV when you want to hand the plan to the rest of the team.

Why keep a catalog?

  • Duplicate hidden IDs are easier to catch before they become quest bugs.
  • Base item, display name, and visual hook stay readable in one place.
  • The export gives the rest of the team something more useful than screenshots.

Good first fields

  • Start with an internal ID, hidden ID, and base item.
  • Then add either item_model or CustomModelData depending on the version you ship.
  • Use notes for quest rules, NPC ownership, or pack-side reminders that will matter again later.

How to use the catalog

One entry per custom item. The catalog keeps them searchable, flags clashes and exports the list for the rest of the team.

Internal ID and display name

The internal ID is the name your team uses for the item, such as rp.guild.pass; the display name is what players read. Keeping both stops the visible name from becoming the only reference.

Base item and version

The vanilla item underneath and the version you ship decide which visual hook makes sense: numeric CustomModelData before 1.21.4, item_model and the newer custom_model_data lists from 1.21.4.

Hidden ID, hook, tags, notes

The hidden ID is what commands and villagers check in custom_data. Tags group items by faction, quest or season; notes hold the rules that are easy to forget.

Duplicate flags

The summary counts duplicate hidden IDs and duplicate visual hooks, and each clashing entry is marked, so two items never answer to the same ID or share one model by accident.

Keeping the list safe

It lives in this browser

Entries are stored locally in the browser you use. Another browser or device starts empty, and clearing site data removes the list, so export it now and then.

Export formats

JSON can be imported back later; CSV opens in any spreadsheet; Markdown pastes cleanly into a wiki page or a team chat.

Import before you edit

If a teammate sends a JSON export, import it first and then add your entries, rather than keeping two separate lists.

From catalog to item

The catalog plans items; it does not write commands. Build the actual /give command in the custom item builder, and give the item a model with the item model builder from 1.21.4 or the resource pack generator before that.
