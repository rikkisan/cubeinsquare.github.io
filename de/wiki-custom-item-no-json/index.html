So benutzt du den Custom-Item-Builder: eigene Items, ohne den Befehl von Hand zu schreiben

Ein Custom-Item in Minecraft ist ein Vanilla-Item mit ein paar zusätzlichen Komponenten: Name und Lore für Spieler, eine versteckte ID für deine Logik und ein Modell-Hook für das Resource Pack. Der Builder schreibt diesen /give-Befehl aus einem Formular in der Syntax der gewählten Version – Anführungszeichen und Klammern sind dann nicht mehr dein Problem.

Von Rikki

Custom-Item-Builder öffnenWarum /give nicht funktioniert

Geprüft für die Versionen: Java Edition 1.20 bis 26.3.

Woraus ein Custom-Item besteht

SchichtWo sie liegtWer sie liest
BasisitemDie Item-ID, etwa minecraft:paperDas Spiel: Stapelgröße, Animation, Haltbarkeit
Name und Lorecustom_name, loreSpieler
Versteckte IDcustom_data={item_id:"…"}Deine Befehle, Quests, Läden und Dorfbewohner
Modell-Hookitem_model, custom_model_dataDas Resource Pack

Getrennte Schichten machen ein Item wartbar: Du kannst es für eine neue Saison umbenennen, ohne die Quest zu brechen, die seine versteckte ID prüft, und sein Aussehen ändern, ohne das eine oder das andere anzufassen.

Schritt für Schritt

  1. Befehlsversion. Wähl 1.21.5 – 26.x, 1.21.4, 1.20.5 – 1.21.3 oder vor 1.20.5. Das Formular zeigt nur die Felder, die diese Version kennt.
  2. Basisitem und Anzahl. Wähl die Basis nach dem Verhalten, nicht nur nach dem Aussehen: Papier stapelt bis 64, ein Buch öffnet sich nicht wie ein beschriebenes Buch, eine Karottenrute lässt sich benutzen.
  3. Versteckte ID. Eine stabile, langweilige ID wie rp.guild.pass. Ab 1.20.5 kommt sie in custom_data; davor schreibt der Builder sie als eigenes NBT-Tag.
  4. Name und Lore. Eine Lore-Zeile pro Zeile im Feld. Der Builder ergänzt italic:false, damit der Name nicht wie eine Amboss-Umbenennung aussieht.
  5. Modell. Vor 1.21.4 ist es eine CustomModelData-Zahl, auf die die overrides des Packs reagieren. Ab 1.21.4 nennt item_model eine Item-Definition: cubeinsquare:item/paper/guild_pass liest assets/cubeinsquare/items/item/paper/guild_pass.json, und die Slots float, string, flag und color sind Werte, nach denen diese Datei umschalten kann.
  6. Kopieren und testen. Die Übersicht zeigt die Länge: Über 256 Zeichen braucht der Befehl einen Befehlsblock statt des Chats.

Das Beispiel erklärt

„Beispiel laden“ füllt das Formular mit einem Gildenpass. Im Zweig 1.21.5 – 26.x entsteht:

/give @p minecraft:paper[minecraft:custom_name={text:"Guild archive pass",italic:false},minecraft:lore=[{text:"Stamped for the old city archive.",italic:false}],minecraft:item_model="cubeinsquare:item/paper/guild_pass",minecraft:custom_data={item_id:"rp.guild.pass"},minecraft:custom_model_data={floats:[2047.0f],strings:["guild_pass"],flags:[true],colors:[6138367]}] 1
  • custom_name und lore sind Textkomponenten in SNBT, die Form, die mit 1.21.5 kam.
  • item_model zeigt auf die Item-Definition im Pack.
  • custom_data trägt die versteckte ID, der der Server trauen kann.
  • custom_model_data trägt Werte, die die Item-Definition prüfen kann: einen Float für range_dispatch, einen String für select, ein Flag für condition, eine Farbe für Tönungen.

Derselbe Pass vor 1.20.5 ist ein einziger NBT-Block:

/give @p minecraft:paper{CustomModelData:2047,display:{Name:'{"text":"Guild archive pass","italic":false}',Lore:['{"text":"Stamped for the old city archive.","italic":false}']},cube_item_id:"rp.guild.pass"} 1

Die versteckte ID im Spiel prüfen

Ab 1.20.5 können Item-Prädikate custom_data direkt prüfen. Die erste Zeile reagiert auf jeden Spieler mit dem Pass in der Haupthand; die zweite nimmt einem Spieler einen Pass ab – so kann eine Tür oder ein Laden ihn „ausgeben“:

execute as @a if items entity @s weapon.mainhand *[custom_data~{item_id:"rp.guild.pass"}] run say I carry the guild pass
clear @s *[custom_data~{item_id:"rp.guild.pass"}] 1

Ein umbenanntes Vanilla-Papier fällt bei beiden Prüfungen durch, weil nicht der Name geprüft wird.

Häufige Fehler

  • Die versteckte ID später ändern. Jede Quest, jeder Laden und jeder Handel, der sie prüft, erkennt alte Items nicht mehr. Ändere stattdessen den sichtbaren Namen.
  • item_model zeigt auf ein Modell. Ab 1.21.4 nennt es eine Datei in items/, die wiederum Modelle in models/ nennt. Zeigt es direkt auf einen Modellpfad, erscheint die Textur für fehlende Modelle.
  • Ein Befehl für alle Versionen. Die vier Zweige gibt es, weil sich die Syntax wirklich unterscheidet: Ein Befehl für 1.21.4 nennt das Item in 1.21.5 {"text":…}.

Häufige Fragen

Brauche ich ein Resource Pack?

Nur für ein eigenes Aussehen. Name, Lore und versteckte ID funktionieren in Vanilla ohne Pack.

Wofür ist der Farb-Slot?

Eine Item-Definition kann eine Modellschicht mit Farben aus custom_model_data tönen, ein Modell bedient so mehrere Fraktionsfarben.

Kann ein Dorfbewohner nur das echte Item annehmen?

Ja: Leg dasselbe custom_data in den Preis des Handels. Der Handels-Builder und der Ökonomie-Artikel zeigen, wie.
