Bossleisten für Minecraft-Events: wann eine Leiste den Chat schlägt und wie man einen Countdown baut

Der Chat scrollt weg, ein Titel verblasst nach ein paar Sekunden, und eine Actionbar-Zeile ist verschwunden, bevor die Hälfte der Spieler sie gelesen hat. Eine Bossleiste bleibt oben auf dem Bildschirm, solange das Event läuft, und alle sehen denselben Füllstand. Damit ist sie der Ort für gemeinsamen Zustand: wie viel Zeit bleibt, wie weit ein Ritual ist, in welcher Phase ein Raid steckt.

Ein gut geführtes Event nutzt meist mehrere gleichzeitig: einen Titel zum Start, eine Chatzeile, die sagt, was die Leiste misst, die Leiste selbst für die ganze Dauer und am Ende einen Titel oder eine Chatnachricht. Für die Textseite siehe lesbare Server-Ankündigungen.

Vier Muster, die auf RP-Servern funktionieren

Countdown

„Evakuierungsfenster“, „Das Ritual endet in…“. Die Leiste startet voll und leert sich. Stil progress, Farbe Gelb oder Rot. Das vollständige Rezept steht weiter unten.

Ladung

Die Leiste füllt sich durch Aktionen der Spieler: gebrachte Opfergaben, reparierte Generatoren, abgegebene Stimmen. max ist das Ziel, der Wert kommt aus einem Scoreboard, das dein Event ohnehin zählt:

execute store result bossbar cube:ritual_charge value run scoreboard players get #offerings ritual

Phasen

Ein Raid in vier Stufen: max 4, und value ist die aktuelle Stufe. Wähl einen gekerbten Stil, der sich durch die Stufenzahl teilen lässt (notched_12 für 4 oder 6 Stufen, notched_10 für 5), damit die Phasengrenzen auf Kerben fallen.

Boss-Leben

Für einen eigenen Boss, der mit einem Tag beschworen wurde, kopierst du sein Leben jeden Tick oder jede Sekunde in die Leiste. Setz max auf sein maximales Leben (hier 300); gespeichert wird das abgerundete Leben:

bossbar set cube:event_boss max 300
execute store result bossbar cube:event_boss value run data get entity @e[tag=event_boss,limit=1] Health

Der Selektor muss genau ein Wesen finden. Ist der Boss tot oder entladen, schlägt die zweite Zeile fehl und die Leiste behält den letzten Wert – entferne sie also nach dem Kampf. Verschiedene Gruppen können verschiedene Leisten sehen, jede mit eigenem Selektor, etwa players @a[team=defenders].

Regeln für lesbare Event-Anzeigen

  • Eine Leiste für einen Zustand. Müssen Spieler zwei Dinge verfolgen, nimm zwei Leisten, aber selten mehr als zwei gleichzeitig.
  • Ein kurzer Titel. Er steht klein über der Leiste. „Evakuierung“ oder „Ritual 65 %“ liest sich schneller als ein Satz.
  • Farben, die immer dasselbe bedeuten. Etwa Rot für Gefahr, Gelb für Timer, Lila für Magie. Nach ein, zwei Events kennen die Spieler den Code.
  • Einmal erklären. Wenn die Leiste zum ersten Mal erscheint, schreib in den Chat, was sie misst und was passiert, wenn sie voll oder leer ist.
  • Sauber beenden. Entferne die Leiste nach dem Event. Eigene Bossleisten werden mit der Welt gespeichert – die Leiste des gestrigen Raids übersteht einen Neustart.

Ein funktionierender Countdown

Eine Bossleiste zählt nicht von selbst. Die Restzeit liegt in einem Scoreboard, wird nach Plan verringert und in die Leiste kopiert. Wichtig ist nur die Einheit: Ein Wiederhol-Befehlsblock läuft jeden Spieltick, 20-mal pro Sekunde. Eine Schleife, die pro Durchlauf 1 abzieht, zählt also Ticks, nicht Sekunden. Ein „60-Sekunden“-Timer mit dem Wert 60 wäre nach drei Sekunden vorbei.

Mit Befehlsblöcken (in Ticks)

Einrichtung, einmal aus dem Chat oder einem Impuls-Block. 60 Sekunden sind 1200 Ticks:

/scoreboard objectives add event_timer dummy
/scoreboard players set #timer event_timer 1200
/bossbar add cube:evacuation {"text":"Evacuation","color":"yellow"}
/bossbar set cube:evacuation color yellow
/bossbar set cube:evacuation max 1200
/bossbar set cube:evacuation value 1200
/bossbar set cube:evacuation players @a

Die Schleife ist ein Wiederhol-Block mit vier Ketten-Blöcken dahinter, alle auf „Immer aktiv“, in dieser Reihenfolge (Befehlsblöcke nehmen die Befehle mit oder ohne Schrägstrich):

execute if score #timer event_timer matches 1.. run scoreboard players remove #timer event_timer 1
execute if score #timer event_timer matches 0.. store result bossbar cube:evacuation value run scoreboard players get #timer event_timer
execute if score #timer event_timer matches 0 run say Das Evakuierungsfenster ist geschlossen.
execute if score #timer event_timer matches 0 run bossbar remove cube:evacuation
execute if score #timer event_timer matches 0 run scoreboard players set #timer event_timer -1

Der erste Block zieht nur ab, solange Zeit übrig ist. Der zweite kopiert die Zeit in die Leiste. Bei null führen die letzten drei deinen Event-Befehl aus, entfernen die Leiste und parken den Timer bei -1, damit sich in den folgenden Ticks nichts wiederholt. Erneutes Ausführen der Einrichtung startet den Countdown neu.

Mit einem Datenpaket (in Sekunden)

Im Datenpaket lässt sich die Arbeit pro Tick ganz vermeiden: Eine Funktion plant sich einmal pro Sekunde selbst neu ein. Drei Dateien im Namensraum cube (vor 1.21 heißt der Ordner functions, nicht function):

data/cube/function/evacuation/start.mcfunction

scoreboard objectives add event_timer dummy
scoreboard players set #timer event_timer 60
bossbar add cube:evacuation {"text":"Evacuation","color":"yellow"}
bossbar set cube:evacuation color yellow
bossbar set cube:evacuation max 60
bossbar set cube:evacuation value 60
bossbar set cube:evacuation players @a
schedule function cube:evacuation/second 1s replace

data/cube/function/evacuation/second.mcfunction

scoreboard players remove #timer event_timer 1
execute store result bossbar cube:evacuation value run scoreboard players get #timer event_timer
bossbar set cube:evacuation players @a
execute if score #timer event_timer matches 1.. run schedule function cube:evacuation/second 1s replace
execute if score #timer event_timer matches ..0 run function cube:evacuation/finish

data/cube/function/evacuation/finish.mcfunction

bossbar remove cube:evacuation
say Das Evakuierungsfenster ist geschlossen.

Gestartet wird mit /function cube:evacuation/start. Die players-Zeile in second nimmt alle auf, die während des Countdowns eingeloggt haben. Zwischen den Sekunden läuft nichts, und /schedule clear cube:evacuation/second stoppt den Countdown vorzeitig (danach die Leiste entfernen).

Häufige Fehler

  • Die Leiste ist unsichtbar. players lief nie oder lief, als niemand online war.
  • Der Timer endet 20-mal zu schnell. Die Schleife zählt Ticks, während max und der Punktestand in Sekunden gesetzt wurden.
  • Die Einrichtung schlägt beim zweiten Mal fehl. bossbar add stoppt an einer vorhandenen ID. Entferne zuerst die alte Leiste oder überspring die add-Zeile.
  • Die Leiste von gestern ist noch zu sehen. Entferne Leisten nach jedem Event und prüf /bossbar list.
  • Die Leiste trägt Text. Muss eine Nachricht gelesen statt beobachtet werden, gehört sie in den Chat oder einen Titel.

Häufige Fragen

Kann jeder Spieler einen eigenen Timer haben?

Nicht mit einer Leiste: Ihr Wert ist für alle gleich, die sie sehen. Für persönliche Timer nimm die Actionbar oder einen Punktestand pro Spieler.

Ticks oder Sekunden?

Sekunden mit /schedule, wenn ein Schritt pro Sekunde genau genug ist. Ticks mit einem Wiederhol-Block oder einer Tick-Funktion, wenn die Leiste ganz gleichmäßig ablaufen soll.

Kann der Titel die Restsekunden zeigen?

Nicht von selbst. Der Name wird beim Ausführen von bossbar set … name festgelegt; man müsste ihn jede Sekunde neu setzen. Den meisten Events reichen ein kurzer Titel und die Leiste selbst.

Funktioniert das in Bedrock?

Nein. /bossbar und /schedule sind Befehle der Java Edition.
