Bossbar-Builder: was jeder /bossbar-Befehl macht

Der Builder macht aus ein paar Feldern sieben Befehle: einer erstellt die Leiste, sechs richten sie ein. Diese Anleitung erklärt jede Zeile, wo sie hingehört und an welchen kleinen Regeln eine Bossleiste scheitert oder hängen bleibt: doppelte IDs, Spieler, die später einloggen, und Leisten, die einen Neustart überleben.

Von Rikki

Bossbar-Builder öffnenEvent-Anzeigen und Countdowns

Geprüft für die Versionen: Java Edition 1.13–26.3. In der Bedrock Edition gibt es /bossbar nicht.

Was der Builder ausgibt

Mit der Vorlage Ritual charge sieht die Ausgabe so aus:

/bossbar add cube:ritual_charge {"text":"Ritual charge","color":"white"}
/bossbar set cube:ritual_charge color purple
/bossbar set cube:ritual_charge style notched_10
/bossbar set cube:ritual_charge max 100
/bossbar set cube:ritual_charge value 65
/bossbar set cube:ritual_charge players @a
/bossbar set cube:ritual_charge visible true

colorblue, green, pink, purple, red, white oder yellow.Die Farbe färbt auch den Titel, aber nur, wenn der Name keine eigene Farbe hat. Der Builder schreibt "color":"white" in den Namen, deshalb bleibt der Titel weiß.
styleprogress (durchgehend) oder notched_6, notched_10, notched_12, notched_20.Die Kerben werden nur darübergezeichnet; der Füllstand bleibt value ÷ max.
maxDer Wert einer vollen Leiste, von 1 bis 2147483647.Dieselbe Einheit wie bei value: Sekunden, Ticks, Phasen oder Lebenspunkte.
valueDer aktuelle Füllstand, ab 0.Der Builder hält ihn höchstens auf max; ein größerer Wert zeigt einfach eine volle Leiste.

max, value und Stil wählen

Eine Bossleiste zeigt nur ein Verhältnis. Leg deshalb zuerst fest, was eine Einheit bedeutet. Bei einem Timer ist max die Dauer des Events in dem, was deine Update-Schleife zählt: Sekunden, wenn sie einmal pro Sekunde läuft, Ticks, wenn sie jeden Tick läuft. Bei einem Ritual, das sich mit Opfergaben füllt, ist max die Zahl der Gaben. Bei einem Raid in Stufen die Zahl der Stufen.

Gekerbte Stile helfen, wenn Spieler mitzählen sollen. Wähl eine Segmentzahl, die sich glatt durch dein max teilen lässt: Bei vier Phasen gibt notched_12 jeder Phase drei Segmente, bei notched_6 liegen die Phasengrenzen zwischen den Kerben. Für Countdowns und alles Fließende liest sich progress am besten.

Die vier Vorlagen sind Ausgangspunkte: Ritual charge (65 von 100), Raid phase II (Phase 2 von 4), Evacuation: 3 minutes (180 von 300 Sekunden übrig) und Phase break incoming (8 von 12). Ändere vor dem Einsatz die ID, damit sich nie zwei Events eine Leiste teilen.

Chat, Befehlsblöcke oder Funktionsdatei

  • Chat. Zeilen einzeln einfügen; der Chat nimmt einen Befehl pro Nachricht. Gut, um das Aussehen vor dem Event zu testen.
  • Befehlsblöcke. Eine Zeile pro Block. Die Einrichtung läuft einmal: Impuls-Blöcke hinter einem Knopf oder eine Kette, die ein einzelner Impuls-Block startet. add gehört nicht in einen Wiederhol-Block: Ab dem zweiten Durchlauf schlägt der Befehl fehl, weil die Leiste existiert, und jedes set mit unverändertem Wert meldet ebenfalls einen Fehlschlag – das bricht bedingte Ketten.
  • Funktionsdateien. In einer .mcfunction-Datei steht jeder Befehl in einer eigenen Zeile, ohne führenden Schrägstrich. Entferne das / aus jeder Zeile des Builders, sonst lädt die Funktion nicht.

Die Leiste während des Events ändern

Existiert die Leiste, führ nur die Zeile aus, die sich ändert:

/bossbar set cube:ritual_charge value 80
/bossbar set cube:ritual_charge name {"text":"The circle is complete","color":"gold"}
/bossbar set cube:ritual_charge color yellow

Soll die Leiste einer echten Zahl folgen, kopier sie jeden Tick oder jede Sekunde aus einem Scoreboard:

execute store result bossbar cube:ritual_charge value run scoreboard players get #offerings ritual

Einen kompletten Countdown nach diesem Muster findest du im Artikel über Event-Anzeigen. Für Spieler, die mitten in der Szene dazukommen, führ /bossbar set cube:ritual_charge players @a erneut aus, zum Beispiel in derselben Schleife. Ist niemand Neues online, meldet der Befehl einen harmlosen Fehlschlag.

Die Leiste entfernen

Eigene Bossleisten werden in der Welt gespeichert (in level.dat). Eine vergessene Leiste ist also auch nach einem Serverneustart noch da. Wenn die Szene vorbei ist:

/bossbar remove cube:ritual_charge
/bossbar list

list zeigt alle noch vorhandenen Leisten – nach jedem Event ausführen, um Reste zu finden. Brauchst du dieselbe Leiste morgen wieder, blendet visible false sie aus und behält die Einstellungen.

Der Titeltext in verschiedenen Versionen

Der Builder schreibt den Namen als {"text":"…","color":"white"}. Bis 1.21.4 liest das Spiel das als JSON. Seit 1.21.5 werden Textkomponenten in Befehlen als SNBT geschrieben, und diese Form bleibt gültig, weil SNBT Schlüssel in Anführungszeichen erlaubt – dieselbe Zeile funktioniert vor und nach der Änderung. Die kurze Form {text:"…"} ohne Anführungszeichen geht erst ab 1.21.5. Ohne Formatierung funktioniert überall auch ein einfacher String wie "Ritual charge".

Häufige Fragen

Zählt eine Bossleiste von selbst herunter?

Nein. Sie zeigt den zuletzt gesetzten Wert. Ein Wiederhol-Block oder eine geplante Funktion muss sie aktualisieren; siehe das Countdown-Rezept.

Können verschiedene Spieler verschiedene Leisten sehen?

Ja. Erstelle pro Gruppe eine Leiste mit eigenem Selektor, zum Beispiel @a[team=red] und @a[team=blue].

Warum wird meine Leiste nicht angezeigt?

Meist lief die players-Zeile nie, lief, bevor die Spieler online waren, oder visible steht auf false. /bossbar get cube:ritual_charge players sagt, wie viele Spieler sie gerade sehen.

Funktioniert das in Bedrock?

Nein. /bossbar ist ein Befehl der Java Edition.
