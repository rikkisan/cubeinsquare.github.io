Как пользоваться конструктором кастомных предметов: предметы без ручного написания команды

Кастомный предмет в Minecraft — это ванильный предмет с несколькими компонентами: имя и лор для игроков, скрытый ID для вашей логики и хук модели для ресурс-пака. Конструктор пишет такую команду /give по форме в синтаксисе выбранной версии, и правила кавычек и скобок перестают быть вашей заботой.

Открыть конструкторПочему не работает /give

Проверено на версиях: Java Edition 1.20–26.3.

Из чего состоит кастомный предмет

СлойГде хранитсяКто его читает
Базовый предметID предмета, например minecraft:paperИгра: размер стака, анимация, прочность
Имя и лорcustom_name, loreИгроки
Скрытый IDcustom_data={item_id:"…"}Ваши команды, квесты, магазины и жители
Хук моделиitem_model, custom_model_dataРесурс-пак

Раздельные слои и делают предмет удобным в поддержке: его можно переименовать к новому сезону, не сломав квест, который проверяет скрытый ID, и сменить арт, не трогая ни того, ни другого.

По шагам

  1. Версия команды. Выберите 1.21.5 – 26.x, 1.21.4, 1.20.5 – 1.21.3 или до 1.20.5. Форма показывает только поля, которые эта версия умеет.
  2. Базовый предмет и количество. Выбирайте основу по поведению, а не только по виду: бумага стакается до 64, книга не открывается как написанная, удочку с морковкой можно использовать.
  3. Скрытый ID. Стабильный и скучный, например rp.guild.pass. С 1.20.5 он ложится в custom_data; до этого конструктор пишет его своим тегом NBT.
  4. Имя и лор. Одна строка лора — одна строка поля. Конструктор добавляет italic:false, чтобы имя не выглядело переименованием на наковальне.
  5. Модель. До 1.21.4 это одно число CustomModelData, на которое реагируют overrides пака. С 1.21.4 item_model называет item definition: cubeinsquare:item/paper/guild_pass читает assets/cubeinsquare/items/item/paper/guild_pass.json, а ячейки float, string, flag и color — значения, по которым этот файл может переключаться.
  6. Скопируйте и проверьте. Сводка показывает длину: больше 256 символов — команде нужен командный блок вместо чата.

Пример по частям

«Загрузить пример» заполняет форму пропуском гильдии. В ветке 1.21.5 – 26.x получается:

/give @p minecraft:paper[minecraft:custom_name={text:"Guild archive pass",italic:false},minecraft:lore=[{text:"Stamped for the old city archive.",italic:false}],minecraft:item_model="cubeinsquare:item/paper/guild_pass",minecraft:custom_data={item_id:"rp.guild.pass"},minecraft:custom_model_data={floats:[2047.0f],strings:["guild_pass"],flags:[true],colors:[6138367]}] 1
  • custom_name и lore — текстовые компоненты в SNBT, в форме, которая появилась в 1.21.5.
  • item_model указывает на item definition в паке.
  • custom_data несёт скрытый ID, которому может доверять сервер.
  • custom_model_data несёт значения, которые проверяет item definition: float для range_dispatch, строку для select, флаг для condition, цвет для окраски.

Тот же пропуск до 1.20.5 — один блок NBT:

/give @p minecraft:paper{CustomModelData:2047,display:{Name:'{"text":"Guild archive pass","italic":false}',Lore:['{"text":"Stamped for the old city archive.","italic":false}']},cube_item_id:"rp.guild.pass"} 1

Как проверить скрытый ID в игре

С 1.20.5 предикаты предметов умеют проверять custom_data напрямую. Первая строка срабатывает на каждого игрока с пропуском в основной руке; вторая забирает у игрока один пропуск — так дверь или магазин могут его «потратить»:

execute as @a if items entity @s weapon.mainhand *[custom_data~{item_id:"rp.guild.pass"}] run say I carry the guild pass
clear @s *[custom_data~{item_id:"rp.guild.pass"}] 1

Переименованная ванильная бумага не проходит ни одну проверку: имя здесь не проверяется.

Частые ошибки

  • Сменить скрытый ID потом. Все квесты, магазины и сделки, которые его проверяют, перестают узнавать старые предметы. Меняйте видимое имя.
  • item_model указывает на модель. С 1.21.4 он называет файл в items/, а тот уже называет модели в models/. Путь сразу на модель даёт текстуру отсутствующей модели.
  • Одна команда для всех версий. Четыре ветки существуют потому, что синтаксис действительно разный: команда для 1.21.4 в 1.21.5 назовёт предмет {"text":…}.

Частые вопросы

Нужен ли ресурс-пак?

Только для своего вида. Имя, лор и скрытый ID работают в ванилле без пака.

Зачем ячейка цвета?

Item definition может окрашивать слой модели цветами из custom_model_data, и одна модель служит нескольким фракционным цветам.

Может ли житель принимать только настоящий предмет?

Да: положите тот же custom_data в цену сделки. Как это сделать, показывают конструктор торгов и статья про экономику.
