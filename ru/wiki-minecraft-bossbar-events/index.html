Боссбары для событий в Minecraft: когда шкала лучше чата и как сделать обратный отсчёт

Чат уезжает вверх, заголовок гаснет через несколько секунд, а строка над хотбаром исчезает раньше, чем её прочтёт половина игроков. Боссбар висит наверху экрана, пока идёт событие, и все видят одно и то же заполнение. Поэтому он нужен для общего состояния: сколько осталось времени, насколько продвинулся ритуал, какая фаза у рейда.

Проверено на версиях: Java Edition 1.15–26.3 (/schedule … replace и /schedule clear появились в 1.15, остальное работает с 1.13). Названия папок датапака ниже — для 1.21 и новее.

Хорошо проведённое событие обычно использует несколько каналов сразу: заголовок на старте, одна строка в чате о том, что показывает шкала, сама шкала на всё время события и заголовок или сообщение в конце. Про текстовую часть — в статье о читаемых объявлениях на сервере.

Четыре приёма, которые работают на RP-серверах

Обратный отсчёт

«Окно эвакуации», «Ритуал завершится через…». Шкала начинается полной и убывает. Стиль progress, цвет жёлтый или красный. Полный рецепт — ниже.

Заряд

Шкала наполняется от действий игроков: принесённые подношения, починенные генераторы, поданные голоса. max — цель, а значение берётся из scoreboard, который событие уже считает:

execute store result bossbar cube:ritual_charge value run scoreboard players get #offerings ritual

Фазы

Рейд из четырёх этапов: max 4, а value — текущий этап. Берите стиль с делениями, кратными числу этапов (notched_12 для 4 или 6 этапов, notched_10 для 5), чтобы границы фаз совпадали с засечками.

Здоровье босса

Для своего босса, призванного с тегом, копируйте здоровье в шкалу каждый тик или каждую секунду. max — максимальное здоровье босса (здесь 300); сохраняется здоровье, округлённое вниз:

bossbar set cube:event_boss max 300
execute store result bossbar cube:event_boss value run data get entity @e[tag=event_boss,limit=1] Health

Селектор должен находить ровно одну сущность. Если босс погиб или выгружен, вторая строка падает, а шкала остаётся на последнем значении — поэтому удаляйте её после боя. Разным группам можно показывать разные шкалы, у каждой свой селектор, например players @a[team=defenders].

Правила читаемого интерфейса события

  • Одна шкала — одно состояние. Если игрокам нужно следить за двумя вещами, сделайте две шкалы, но редко больше двух одновременно.
  • Короткий заголовок. Он написан мелко над шкалой. «Эвакуация» или «Ритуал 65%» читается быстрее предложения.
  • Цвета, которые всегда значат одно и то же. Например, красный — опасность, жёлтый — таймер, фиолетовый — магия. После пары событий игроки запоминают код.
  • Объясните один раз. Когда шкала появляется впервые, напишите в чат, что она измеряет и что будет, когда она заполнится или опустеет.
  • Завершайте. Удаляйте шкалу после события. Свои боссбары сохраняются в мире, так что шкала вчерашнего рейда переживёт перезапуск.

Рабочий обратный отсчёт

Боссбар сам не считает. Оставшееся время хранится в scoreboard, уменьшается по расписанию и копируется в шкалу. Главное — не перепутать единицы: повторяющийся командный блок срабатывает каждый игровой тик, 20 раз в секунду, поэтому цикл, который вычитает 1 за срабатывание, считает тики, а не секунды. «60-секундный» таймер со значением 60 закончится за три секунды.

На командных блоках (счёт в тиках)

Настройка, один раз из чата или импульсного блока. 60 секунд — это 1200 тиков:

/scoreboard objectives add event_timer dummy
/scoreboard players set #timer event_timer 1200
/bossbar add cube:evacuation {"text":"Evacuation","color":"yellow"}
/bossbar set cube:evacuation color yellow
/bossbar set cube:evacuation max 1200
/bossbar set cube:evacuation value 1200
/bossbar set cube:evacuation players @a

Цикл — один повторяющийся командный блок и за ним четыре цепных, все в режиме «Всегда активен», в таком порядке (командные блоки принимают команды и со слэшем, и без):

execute if score #timer event_timer matches 1.. run scoreboard players remove #timer event_timer 1
execute if score #timer event_timer matches 0.. store result bossbar cube:evacuation value run scoreboard players get #timer event_timer
execute if score #timer event_timer matches 0 run say Окно эвакуации закрыто.
execute if score #timer event_timer matches 0 run bossbar remove cube:evacuation
execute if score #timer event_timer matches 0 run scoreboard players set #timer event_timer -1

Первый блок вычитает, только пока время есть. Второй копирует время в шкалу. На нуле последние три блока запускают команду события, удаляют шкалу и ставят таймер на -1, чтобы в следующие тики ничего не повторялось. Повторный запуск настройки перезапускает отсчёт.

В датапаке (счёт в секундах)

В датапаке можно вообще обойтись без работы каждый тик: функция переназначает сама себя раз в секунду. Три файла в пространстве имён cube (до 1.21 папка называется functions, а не function):

data/cube/function/evacuation/start.mcfunction

scoreboard objectives add event_timer dummy
scoreboard players set #timer event_timer 60
bossbar add cube:evacuation {"text":"Evacuation","color":"yellow"}
bossbar set cube:evacuation color yellow
bossbar set cube:evacuation max 60
bossbar set cube:evacuation value 60
bossbar set cube:evacuation players @a
schedule function cube:evacuation/second 1s replace

data/cube/function/evacuation/second.mcfunction

scoreboard players remove #timer event_timer 1
execute store result bossbar cube:evacuation value run scoreboard players get #timer event_timer
bossbar set cube:evacuation players @a
execute if score #timer event_timer matches 1.. run schedule function cube:evacuation/second 1s replace
execute if score #timer event_timer matches ..0 run function cube:evacuation/finish

data/cube/function/evacuation/finish.mcfunction

bossbar remove cube:evacuation
say Окно эвакуации закрыто.

Запуск — /function cube:evacuation/start. Строка players в second добавляет тех, кто зашёл во время отсчёта. Между секундами ничего не выполняется, а /schedule clear cube:evacuation/second останавливает отсчёт досрочно (шкалу после этого удалите).

Частые ошибки

  • Шкалы не видно. players не выполнялась или выполнилась, когда никого не было онлайн.
  • Таймер заканчивается в 20 раз быстрее. Цикл считает тики, а max и счёт заданы в секундах.
  • Настройка падает со второго раза. bossbar add останавливается на существующем ID. Сначала удалите старую шкалу или пропустите строку add.
  • Вчерашняя шкала всё ещё на экране. Удаляйте шкалы после каждого события и проверяйте /bossbar list.
  • Шкала несёт текст. Если сообщение нужно прочитать, а не отслеживать, его место в чате или заголовке.

Частые вопросы

Можно дать каждому игроку личный таймер?

Одной шкалой — нет: её значение одинаково для всех, кто её видит. Для личных таймеров используйте actionbar или личный счёт в scoreboard.

Тики или секунды?

Секунды через /schedule, если шага в секунду достаточно. Тики через повторяющийся блок или tick-функцию, если шкала должна убывать совершенно плавно.

Может заголовок показывать оставшиеся секунды?

Сам — нет. Название фиксируется в момент bossbar set … name, так что его пришлось бы задавать заново каждую секунду. Большинству событий хватает короткого заголовка и самой шкалы.

Это работает в Bedrock?

Нет. /bossbar и /schedule — команды Java Edition.
