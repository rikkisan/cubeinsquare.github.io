От модели в Blockbench к предмету в игре: экспорт, пути в паке и подключение

Blockbench делает модель, а ресурс-пак решает, какой предмет её показывает. Файл модели одинаков во всех версиях с 1.13, но способ сказать предмету, какую модель использовать, изменился в 1.21.4, поэтому последний шаг зависит от вашей версии.

Конструктор item_modelСтруктура ресурс-пака

Проверено на версиях: Java Edition 1.20–26.3. Форматы Bedrock в Blockbench в Java Edition не работают.

В Blockbench

  • Используйте формат «Java Block/Item». Он соблюдает правила игры: каждый куб должен оставаться в пределах от −16 до 32 по каждой оси (три блока), а куб вращается только вокруг одной оси, шагами по 22,5° до 45°, которые принимает любая версия.
  • Настройте отображение. Вкладка Display решает, как модель сидит в руке, на голове, в рамке и в инвентаре. Без неё большая модель заполняет ячейку хотбара или висит рядом с рукой.
  • Называйте текстуры по пути в паке. Текстура, сохранённая как assets/cube/textures/item/guild_hammer.png, указывается как cube:item/guild_hammer. Blockbench записывает эту ссылку в модель, так что путь должен быть верным уже при экспорте.
  • Экспортируйте через File → Export → Export Block/Item Model в assets/cube/models/item/.

Куда кладутся файлы

my_pack/
  pack.mcmeta
  assets/cube/
    items/guild_hammer.json          (1.21.4+ only)
    models/item/guild_hammer.json    (exported from Blockbench)
    textures/item/guild_hammer.png

Для новых файлов используйте своё пространство имён (здесь cube), а не minecraft, чтобы они не пересеклись с ванильными ресурсами или другим паком.

Подключение к предмету в 1.21.4 и новее

Item definition в items/ говорит, какую модель рисовать:

{
  "model": {
    "type": "minecraft:model",
    "model": "cube:item/guild_hammer"
  }
}

Предмет указывает на этот файл компонентом item_model, одинаково в 1.21.4 и 1.21.5 – 26.x:

/give @p minecraft:stick[minecraft:item_model="cube:guild_hammer"] 1

Одна модель может обслуживать несколько состояний предмета (заряжен, сломан, цвета фракций) через select, range_dispatch или condition в definition; эти файлы пишет конструктор item_model.

Подключение в 1.21.3 и старше

В старых версиях папки items/ нет. Вместо неё модель ванильного предмета получает override, который переключается по CustomModelData, в assets/minecraft/models/item/stick.json:

{
  "parent": "minecraft:item/handheld",
  "textures": { "layer0": "minecraft:item/stick" },
  "overrides": [
    { "predicate": { "custom_model_data": 1 }, "model": "cube:item/guild_hammer" }
  ]
}

Команда задаёт число — компонентами в 1.20.5 – 1.21.3 или NBT до этого:

/give @p minecraft:stick[minecraft:custom_model_data=1] 1
/give @p minecraft:stick{CustomModelData:1} 1

С 1.21.4 overrides игнорируются — это самая частая причина, по которой пак, который «в прошлом году работал», показывает только ванильные предметы.

Если модель не появилась

  • Фиолетово-чёрная клетка на модели: модель загрузилась, текстура — нет. Сравните ссылку на текстуру внутри JSON модели с настоящим путём к PNG.
  • Фиолетово-чёрный куб вместо модели: файл модели не найден или не загрузился. Проверьте путь в item definition или в override и найдите имя файла в логе игры.
  • Огромная или не на месте в руке: настройки Display остались по умолчанию.
  • После правки ничего не изменилось: нажмите F3+T в игре, чтобы перезагрузить ресурс-паки; перезапуск не нужен.
  • Пак помечен как несовместимый: pack.mcmeta объявляет формат другой версии. Номер для каждого релиза есть на странице «Pack format» в Minecraft Wiki.

Частые вопросы

Может одна модель использоваться несколькими предметами?

Да. Несколько item definitions или несколько overrides могут указывать на один файл модели.

Можно ли анимировать текстуру?

Да: вертикальная полоса кадров в PNG и файл .png.mcmeta рядом, в котором задано время кадра.

Какой базовый предмет должен нести модель?

Тот, чьё поведение подходит: палка или удочка с морковкой для реквизита, меч или топор для оружия, бумага для документов. Модель меняет только вид.
